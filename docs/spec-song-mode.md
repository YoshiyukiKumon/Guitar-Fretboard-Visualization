# ソングモード（コード進行・伴奏再生）

曲単位でコード進行を登録し、ストロークパターンに沿った **伴奏（バッキング）** を再生する機能の仕様。  
編集は **ライブラリ**、再生・練習は **ソングモード** に分離する。

## 目的

- コード進行に合わせた伴奏を鳴らし、曲全体の練習を可能にする
- ライブラリの **コード**・**ストロークパターン** を参照して再利用する
- ダイアトニック以外・小節内コードチェンジ・転調に対応する
- 指板への反映は行うが、**押さえ方（ポジション）登録は将来対応** とし v1 では実装しない

## アプリモード

ヘッダーのモード切替（左から順）:

| 順 | モード | 内容 |
|----|--------|------|
| 1 | **練習** | 現行 UI（キー・スケール・コード、指板、構成音） |
| 2 | **ライブラリ** | スケール / コード / ストローク / **ソング** の編集 |
| 3 | **ソング** | 曲選択・伴奏再生・進行チャート表示・指板（現在コード） |
| 4 | **設定** | 既存設定 |

- `appMode` に `song` を追加。既定は **練習**
- ナビ表示名: 日本語 **ソング** / English **Song**（詳細は i18n 仕様に従う）

### 指板連動（v1）

- 再生中の **現在コード** に応じ、ソングモード内の指板表示を更新する
- 反映内容: **コードルート**（`chordRootKeyId`）+ `chordId`（練習モードの chordKey + chord と同型）
- **曲キー**（転調）は指板のコード強調には使わない（コードルートはイベントごとに指定）
- **押さえ方は指定しない** — 指板は従来どおり全ポジションを表示（強調ルールは練習モードのコードビュー相当）
- 練習モード側の `localStorage` 選択値は、ソング再生中 **上書きしない**（モード切替時に各モードの状態を維持）

## 実装状況（v1）

**結論: 編集機能は v1 で実装済み。** ただし編集 UI は **ライブラリモード** にあり、**ソングモード（再生タブ）では編集できない**。

### 編集の場所

| モード / タブ | 編集 | 説明 |
|---------------|------|------|
| **ライブラリ > ブロック** | ×（v1.8 で廃止） | — |
| **ライブラリ > 曲** | ○ | 曲メタ・parts・**セクション（旧ブロック）** の CRUD |

## データモデル

### 型定義

```typescript
/** 小節内の 1 コード（拍位置付き） */
interface SongChordEvent {
  /** 小節内開始位置（4 分音符拍単位、0 起点） */
  offsetBeats: number;
  /** コードのルート（例: Am7 なら A）。曲キー（転調）とは別 */
  chordRootKeyId: string;
  /** ライブラリのコード ID（組み込み + カスタム） */
  chordId: string;
}

/** 小節に付ける記号・指示 */
interface SongMeasureMarkers {
  /** リピート開始 ||: （以降 :|| までを反復） */
  repeatStart?: boolean;
  /** リピート終了 :|| */
  repeatEnd?: boolean;
  /** セーニョ 𝄋（D.S. の跳び先） */
  segno?: boolean;
  /** フィーネ 𝄑（D.C. / D.S. al Fine の終点） */
  fine?: boolean;
  /** コーダ 𝄌（跳び先。通常は曲後半に 1 箇所） */
  coda?: boolean;
  /** To 𝄌（ここまで演奏後コーダへ跳躍） */
  toCoda?: boolean;
  /** 1. 括弧（ファーストエンディング） */
  firstEnding?: boolean;
  /** 2. 括弧（セカンドエンディング） */
  secondEnding?: boolean;
  /** 3. 括弧（サードエンディング） */
  thirdEnding?: boolean;
  /** ダ・カーポ al Fine（先頭からフィーネまで） */
  daCapoAlFine?: boolean;
  /** ダル・セーニョ al Fine（セーニョからフィーネまで） */
  dalSegnoAlFine?: boolean;
  /** ダ・カーポ al Coda（先頭から To 𝄌 まで → コーダ → 終了） */
  daCapoAlCoda?: boolean;
  /** ダル・セーニョ al Coda（セーニョから To 𝄌 まで → コーダ → 終了） */
  dalSegnoAlCoda?: boolean;
}

/** 1 小節 */
interface SongMeasure {
  /**
   * 曲キー（転調）の変更。
   * 指定した小節 **以降**、次に keyId が指定されるまでこのキーを継承する。
   * コード単位では変更しない。
   */
  keyId?: string;
  /**
   * 拍子 override（例: "4/4"）。
   * 省略時は曲の defaultTimeSignature → 直前小節を継承
   */
  timeSignature?: string;
  /**
   * ストローク override（ライブラリ ID）。
   * 省略時は曲の strumPatternId → 直前小節を継承
   */
  strumPatternId?: string;
  /** 繰り返し・跳躍記号 */
  markers?: SongMeasureMarkers;
  /** 小節内コード（offsetBeats 昇順、同一 offset 不可）。記号のみの小節は空配列可 */
  events: SongChordEvent[];
}

/**
 * ブロック（マスター）。
 * ラベル単位（Intro / A / B 等）で小節をまとめ、複数の曲から参照する。
 */
interface SongBlockDef {
  id: string;
  /** 表示ラベル（自由入力）。例: "Intro", "A", "B", "Solo" */
  label: string;
  /** ブロック内小節（1 要素 = 1 小節） */
  measures: SongMeasure[];
}

/** 曲構成の 1 要素 */
type SongPart =
  | {
      type: 'block';
      /** 挿入するブロック ID（マスター参照） */
      blockId: string;
      /** true = 参照のみ（編集不可）。CSV では blockRef: */
      reference?: boolean;
    }
  | {
      type: 'inline';
      /** 曲に直接属する小節（個別編集可） */
      measures: SongMeasure[];
    };

/** 曲定義 */
interface SongDef {
  id: string;
  name: string;
  /** 曲の開始キー（1 小節目以前の effectiveKeyId） */
  defaultKeyId: string;
  /** 既定拍子（例: "4/4"） */
  defaultTimeSignature: string;
  /** 既定 BPM。省略時は設定の bpm を使用 */
  bpm?: number;
  /** 伴奏ストローク（ライブラリ ID） */
  strumPatternId: string;
  /**
   * 曲構成（上から順）。
   * ブロック参照とインライン小節を混在できる。
   */
  parts: SongPart[];
  /**
   * 曲全体の再生回数。
   * 内部の繰り返し記号を展開した **1 通り** を 1 回と数える。
   * - `1` … 1 回のみ（既定）
   * - `n` … n 回
   * - `0` … 無限ループ（UI では ∞ 表示）
   */
  playCount: number;
}
```

### ブロック（マスター）と曲構成

| 概念 | 説明 |
|------|------|
| **ブロック** | `[Intro]` `[A]` 等のラベル付き小節群。**ライブラリ > ブロック** で編集する大本 |
| **ブロック参照** | 曲の `parts` に `{ type: 'block', blockId }` として挿入。中身は **参照時点のマスター** を展開 |
| **インライン小節** | 曲の `parts` に `{ type: 'inline', measures }` として直接記述。**曲編集画面で自由に修正** |

#### 編集ルール

| 対象 | 曲編集 UI | ブロック編集 UI |
|------|-----------|-----------------|
| ブロック参照の中身 | **編集不可**（読取専用プレビュー）。「大本を編集」リンクでブロックタブへ | 編集可 |
| ブロック参照自体 | **差替・削除・並べ替え** 可 | — |
| インライン小節 | **追加・修正・削除・挿入** 可 | — |

- ブロックマスターを更新すると、そのブロックを参照する **すべての曲** の展開結果に反映される
- 曲側でブロック内小節を直接いじることはできない（インライン化は v1 では **非対応** → [SONG-F-007](#song-f-007)。必要ならインライン小節を新規追加して手入力）

#### 曲の平坦化（再生・展開前）

```
parts[] 上から順に:
  block → findBlockById(blockId).measures を連結
  inline → measures を連結
→ 生の measures[]（曲全体の 1 次元小節列）
→ 既存の repeat / D.C. / D.S. / playCount 展開
```

- `flattenSongParts(song, blocks): SongMeasure[]` をドメイン層に実装（ユニットテスト必須）
- 平坦化後の小節インデックスで繰り返し記号・コーダ跳躍を解決する

### 曲キー（転調）の継承

**曲キー**はコードのルートとは別概念。音名表記の調号文脈・編集 UI の参考キーなどに用い、**小節単位でのみ変更**する。

各小節 `i` の `effectiveKeyId`（曲キー）— **平坦化後** の小節列に対して:

1. その小節より前で最も近い `keyId` が設定された小節があればそれ
2. なければ `defaultKeyId`

例: 小節 1–4 が C、小節 5 で `keyId: Eb` → 5 小節以降 Eb（小節 10 で再び `keyId: C` なら 10 以降 C）。

**コードのルート**は各 `SongChordEvent.chordRootKeyId` に常に保持（非ダイアトニックは C キー曲中でも `F#` ルート + `7` 等を指定）。曲キーにコードルートを自動代入しない。

### 小節内複数コード

- `offsetBeats` は **4 分音符拍** 単位（ストロークパターン・BPM 計算と同一基準。**内部は 0 始まり**）
- 例（4/4）: `0 → C`, `2 → D7` は 1 小節に 2 コード（**1 拍目 C、3 拍目 D7**）
- **UI の拍番号**は **1 始まり**（1 拍目=1、3 拍目=3）。保存値 `offsetBeats` とは 1 差
- バリデーション:
  - `0 <= offsetBeats < measureQuarterBeats`（当該小節の拍子から算出）
  - 同一小節内で `offsetBeats` の重複不可
  - 各 `chordId` は `findChordById` で解決可能であること

### 伴奏のコード切り替えタイミング

- ストロークの各ヒット時刻 `t` に対し、**その時刻で有効なコード**（`offsetBeats` が最も近い過去のイベント）の構成音を鳴らす
- コード変更拍の **その拍のストロークから** 新コードを適用（拍頭切り替え）

### 繰り返し・跳躍記号

楽譜記号に準じ、小節 `markers` で指定する。再生時は **展開（expand）** してから伴奏をスケジュールする。

| 記号 | フィールド | 意味 |
|------|------------|------|
| `\|\|:` | `repeatStart` | リピート開始。対応する `: \|\|` までを反復 |
| `: \|\|` | `repeatEnd` | リピート終了。直近の未閉じ `\|\|:` へ戻る |
| `1.` | `firstEnding` | 1 回目のみ演奏（2 回目以降はスキップ） |
| `2.` | `secondEnding` | 2 回目のみ演奏（1 回目・3 回目はスキップ） |
| `3.` | `thirdEnding` | 3 回目のみ演奏（1・2 回目はスキップ） |
| `𝄋` | `segno` | セーニョ位置（Noto Music 字体） |
| `Fine` | `fine` | フィーネ位置（終了指示） |
| `Coda` | `coda` | コーダ開始位置 |
| `To Coda` | `toCoda` | ここまで演奏後、コーダへ跳躍 |
| `D.C.` | `daCapoAlFine` | 当該小節到達後、**先頭**から `fine` まで演奏して終了 |
| `D.S.` | `dalSegnoAlFine` | 当該小節到達後、**segno** から `fine` まで演奏して終了 |
| `D.C. al 𝄌` | `daCapoAlCoda` | 先頭 → `toCoda` まで → **コーダ** → 終了 |
| `D.S. al 𝄌` | `dalSegnoAlCoda` | **segno** → `toCoda` まで → **コーダ** → 終了 |

#### リピート（`\|\|:` … `: \|\|`）

- ペアは **入れ子可能**（スタックで管理）
- `: \|\|` 到達時: 対応 `\|\|:` へ 1 回戻る（2 度演奏）。2 回目終了後は `: \|\|` の **次小節** へ進む
- **1. / 2. / 3. 括弧**:
  - 1 回目: `firstEnding` 小節のみ演奏し `secondEnding` / `thirdEnding` をスキップ
  - 2 回目: `secondEnding` 小節のみ演奏し `firstEnding` / `thirdEnding` をスキップ
  - 3 回目: `thirdEnding` 小節のみ演奏し `firstEnding` / `secondEnding` をスキップ
  - 括弧外の小節は毎回演奏
  - `thirdEnding` が曲内に存在する場合、リピートは **最大 3 通過** まで戻る

#### D.C. / D.S.（Fine / Coda）

- 指示フィールドは **指示小節** に付ける（コードが無い小節でも可）
- **同一小節に Fine 系と Coda 系を同時指定不可**（`daCapoAlFine` と `daCapoAlCoda` 等）
- 指示実行後は **当該展開パス内で終了**。`playCount` による全体リピートとは別

| 指示 | 演奏経路 |
|------|----------|
| `daCapoAlFine` | 先頭小節 → `fine` 小節（含む） |
| `dalSegnoAlFine` | `segno` 小節 → `fine` 小節（含む） |
| `daCapoAlCoda` | 先頭小節 → `toCoda` 小節（含む）→ `coda` 小節 → 曲末（`fine` がコーダ以後にあればそこで終了） |
| `dalSegnoAlCoda` | `segno` 小節 → `toCoda` 小節（含む）→ `coda` 小節 → 曲末（同上） |

- `dalSegnoAlFine` / `dalSegnoAlCoda` 使用時、曲内に `segno` が無い → **バリデーションエラー**
- `daCapoAlFine` / `dalSegnoAlFine` 使用時、進行方向に `fine` が無い → **バリデーションエラー**
- `daCapoAlCoda` / `dalSegnoAlCoda` 使用時、曲内に `toCoda` と `coda` が無い → **バリデーションエラー**
- `coda` は曲内 **1 箇所** のみ（複数はエラー）

#### コーダ（To 𝄌 / 𝄌）

- **`toCoda` 〜 `coda` 手前** の小節は、コーダ跳躍時に **スキップ** する（楽譜の「トゥ・コーダ」以降コーダへ行く区間）
- **リピート + To 𝄌**: 2 回目以降の通過で `toCoda` 小節を演奏した直後、**`coda` 小節へ跳躍** し、間の小節をスキップ。コーダ以降を演奏してパス終了（末尾に D.S. al Coda 等があれば続けて処理）
- **通常通過（跳躍なし）**: 楽譜順に演奏。`coda` 小節はスコア上の位置どおり **通過する**（跳躍指示が無い限り省略しない）
- 展開エンジンは `toCoda` / `coda` の小節インデックスを事前に解決し、跳躍時は `codaIndex` へ seek する

#### 展開パイプライン

```
parts[] → flattenSongParts → 生の measures[]
  → repeat / volta 展開（2 回目 To 𝄌 でコーダ跳躍含む）
    → playbackMeasures[]（1 通りの小節列）
  → 末尾等の D.C. / D.S. 指示（Fine / Coda）を適用
    → finalPlaybackMeasures[]
  → playCount 回連結 → 伴奏スケジュール
```

- `expandSongMeasures(song, blocks): ExpandedMeasure[]` — 内部で `flattenSongParts` を呼ぶ
- 展開結果の各要素は `{ sourceMeasureIndex, events, timeSignature, effectiveKeyId, … }` を保持（チャート表示・現在位置表示用）

### 曲全体 n 回再生（playCount）

- 繰り返し記号・D.C. / D.S. を適用した **1 通り** が 1 サイクル
- `playCount = n` … サイクルを n 回連続再生
- `playCount = 0` … サイクルを無限ループ（停止まで）
- 既定値 `1`

### 進行チャート表示（再生用）

**方針: 1 小節 = 1 行にしない。** 横方向のスペースを活かし、**拍幅比例のコードチップ** を折り返し配置する。

#### レイアウト方式: 拍幅比例フロー

- コンテナ幅に応じ、**複数小節を 1 行に詰めて表示** する
- 各コードチップの幅 = `（コードの持続拍数 / 行内の基準拍）× 単位幅`
- 小節線 `|` のほか、記号・**ブロック境界**（`[A]` 等のラベルチップ）を表示
- 折り返し: 行幅を超えたら次行へ（小節途中での改行は **可** — チップ単位で wrap）

```
小節1      小節2        小節3
[C======|Am=====|F====|G=====]
[D==|G==|C========|Am====|…]   ← 幅に応じ折り返し
      ▲ 現在位置（ハイライト + スクロール追従）
```

#### 現在位置

- 再生中のコードチップをハイライト（枠・背景）
- ビューポート外のときは `scrollIntoView({ inline: 'center', block: 'nearest' })`
- 小節番号・拍位置はテキストでも表示（例: `3.2` = 小節 3 の 2 拍目）

#### チップ表示内容

- 短縮ラベル: `{キールート}{コード名}` 例 `Am7`, `F#m7-5`
- 狭幅時: コード名のみ（キーはツールチップ）

#### 未再生 / 編集との関係

- 編集 UI は縦型のまま
- 再生 UI のみ本レイアウトを使用（同一データの別ビュー）
- **表示データ**は `buildSongChartPreviewMeasures`（登録小節そのまま）。**再生スケジュール**は `expandSongMeasures`（リピート・playCount 展開後）

## 音声・再生エンジン

### 概要

- 既存 `TonePlayer` のリピートスケジューラを拡張し、**曲再生セッション** を追加
- 単コード ∞ リピート・スケール/アルペジオオーバーレイと **相互排他**（開始時に他再生を停止）

### スケジューリング

1. `flattenSongParts` → `expandSongMeasures` で **展開済み小節列** を生成（デフォルトは **1 サイクル**。`playCount` 連結は第 3 引数 `playCountOverride` 指定時のみ）
2. 曲全体再生 UI は `playCountOverride` にセッション／曲の `playCount` を渡して連結（0 = 無限）
3. 各小節を拍に展開し、各拍時刻の **有効コード** を決定
4. ストロークパターンのヒットを先読みスケジュール
5. 小節拍子が変わる場合は `measureQuarterBeats` を小節ごとに再計算
6. 展開後の最終小節終了 + **再生ループ回数** 満了で停止（`playCount = 0` は停止までループ）
   - 曲全体再生 UI: `expandSongMeasures` が `playCount` を反映済みのため、`playSong` のループ引数は有限時 **1**・無限時 **0**（二重適用しない）

### 未決定事項（v1 で確定済み）

- 拍子変更小節とストロークパターン拍子が不一致の場合: **曲の strumPatternId の拍子を曲全体で優先** し、小節 `timeSignature` は表示・拍位置計算のみに使用。不一致時は編集保存で **確認ダイアログ付き警告**（`validate-song.ts` → ライブラリ保存 UI）

|------|--------|
| 文字コード | UTF-8 |
| ヘッダー | 1 行目必須 |
| ダウンロード | 組み込み + カスタムの **ブロック・曲** をすべて出力 |
| アップロード | **カスタムの songBlocks / songs のみ置換**（他 type は従来どおり）。組み込み行はスキップ |
| 取り込み前 | 件数プレビュー + 確認ダイアログ |
| 参照整合 | 曲の `parts` が参照する `blockId`・`chordId`・`strumPatternId` は取り込み時に検証 |

### 行タイプ

#### `song-block`

| 列 | 必須 | 説明 |
|----|------|------|
| type | ○ | `song-block` |
| id | ○ | ブロック ID |
| name | ○ | ラベル（`[Intro]` 等。CSV 上は `name` 列を流用） |
| payload | ○ | 小節列のエンコード文字列（後述） |

#### `song`

| 列 | 必須 | 説明 |
|----|------|------|
| type | ○ | `song` |
| id | ○ | 曲 ID |
| name | ○ | 曲名 |
| payload | ○ | メタデータ + `parts` のエンコード文字列（後述） |

※ 既存の scale/chord 行は `tones` 列。song 系は複雑なため **`payload` 列** に集約する（列追加方式）。

拡張ヘッダー例:

```text
type,id,name,tones,payload
scale,...
chord,...
song-block,my-intro,Intro,"..."
song,my-pop,Pop Demo,"..."
```

`tones` 列は song 系行では **空** でよい。

### payload エンコード（小節・parts）

パーサは `src/domain/song/song-csv-codec.ts` に集約する。

#### 小節列（ブロック payload / インライン part）

- 小節区切り: `||`
- 1 小節: `{key}|{timeSig}|{strum}|{markers}|{events}`（`|` は **5 フィールド区切り**、先頭 4 つのみで分割し `events` は残り全体）
  - `key` … 曲キー override（転調）。空 = 継承（エンコード時は `_`）
  - `timeSig` … 拍子（例 `4/4`）。空 = 継承（エンコード時は `_`）
  - `strum` … 小節ストローク override（ライブラリ ID）。空 = 継承（エンコード時は `_`）
  - `markers` … 記号を `+` 結合。空 = `_`
  - `events` … コードを `+` 結合。各コード: `{offset}/{rootKeyId}/{chordId}`。空 = `_`
    - 例: `0/C/maj7+2/A/m7`
- **後方互換**: 旧 4 フィールド `{key}|{timeSig}|{markers}|{events}` も import 時に解釈可能

例（2 小節ブロック）:

```text
_|4/4|_|repeatStart|0/C/maj7||_|_|_|repeatEnd|0/G/maj7
```

旧形式（4 フィールド）の例:

```text
_|4/4|repeatStart|0/C/maj7||_|_|repeatEnd|0/G/maj7
```

#### 曲 payload（メタ + parts）

- セクション区切り: 最初の `::` で **メタ** と **parts** を分離
- **メタ**（`,` 区切り `key=value`）:  
  `defaultKeyId=C,defaultTimeSignature=4/4,strumPatternId=builtin-strum-syncopation,bpm=120,playCount=1`
- **parts**（`||` 区切り）:
  - ブロック参照（編集可）: `block:{blockId}`
  - ブロック参照（読取専用）: `blockRef:{blockId}`
  - インライン小節: `inline:{小節列エンコード}`（上記と同形式）

例:

```text
defaultKeyId=C,defaultTimeSignature=4/4,strumPatternId=builtin-strum-syncopation,bpm=120,playCount=2::block:my-intro||block:my-a||inline:|4/4||0/C/maj7
```

### 取り込み順序

1. `scale` / `chord` / `strum`（将来）— 従来どおり
2. **`song-block`** — 曲より先に取り込む（参照先を確保）
3. **`song`** — ブロック参照を検証してから保存

### UI

- **ブロック** / **曲** タブおよびライブラリ共通フッターに、既存と同じ **CSV ダウンロード / アップロード** を配置
- 1 回のアップロードでスケール・コード・ブロック・曲をまとめて更新可能（type ごとに置換対象を分岐）

### 実装メモ

- 手編集向けに、将来 **JSON 行**（`type=song-json`）を別途足してもよいが v1 は上記 DSL のみ
- エクスポート時は決定的な並び（id 昇順）とし、差分管理しやすくする

### SONG-F-001

**コード押さえ方（Voicing / ポジション）** — 優先度 P2

#### 背景・目的

v1 では指板に全ポジションを表示するのみ。曲ごとに「このコードはこの形で」という練習指示を付けたい。

#### 要件（受入条件）

- `SongChordEvent` に任意の `voicingId` またはフレット配列フィールドを追加できる
- ライブラリ小節エディタでイベントごとに押さえ方を選択・保存できる
- ソング再生中、指板で **当該ポジションのみ**（または強調）表示できる
- 未指定時は v1 同等（全ポジション表示）にフォールバックする
- 既存曲データ（voicing 未指定）は import 互換を維持する

#### データモデル

```typescript
interface SongChordEvent {
  // 既存フィールド …
  /** 任意。未指定時は全ポジション表示（v1 互換） */
  voicingId?: string;
  /** または string[]（弦ごとフレット。`-1` = ミュート） */
  frets?: readonly (number | -1)[];
}
```

#### 想定実装

- ドメイン: `src/domain/song/` 型拡張、`validate-song.ts`
- UI: `library-song-measure-editor.ts`、指板: ソングモード fretboard 連動
- 永続化: `SongDef` / CSV codec 拡張（[SONG-F-009](#song-f-009) と同時検討可）
